# SteamChecker

Steam ライブラリを解析して、タイトルごとに「圧縮すべきか / 圧縮しても無駄か / 消したほうが早いか / 圧縮してはいけないか」を判定するツール。

> **アルファ版です。まずは解析だけ使うことをおすすめします。**
>
> - 解析（スキャン）は**ファイルを一切変更しません**
> - GUI からは圧縮・復元も実行できます。実行前に安全検査（NTFS 確認・Steam 起動中の拒否・
>   ジャンクション検出・空き容量など）と、削減見込みを示す確認ダイアログを必ず通ります
> - 圧縮は可逆です。「元に戻す」でいつでも解除できます
> - CLI から圧縮する場合のみ `--experimental` が必要です（誤爆の質が違うため）
>
> 実機検証の結果は [docs/RESEARCH.md](docs/RESEARCH.md) を参照。

Windows の透過圧縮（WOF / `compact.exe /EXE:LZX`）を使う点は既存ツールと同じ。違うのは **判断を自動化する層** を持っていること。

## 判定ロジック

4 つの入力を突き合わせる。

| 入力 | 取得元 |
|---|---|
| 最終プレイ日時 | `userdata/<id>/config/localconfig.vdf` |
| 最終更新日時・サイズ | `steamapps/appmanifest_<appid>.acf` |
| 実測圧縮率 | ゲームフォルダから層化サンプリングして実測 |
| 技術的制約 | `dstorage*.dll` / EasyAntiCheat / BattlEye / ファイルシステム種別 |

出力は 6 分類。

```
NTFS 以外 / DirectStorage 検出        → 圧縮非推奨
既に圧縮済み                          → 何もしない
削減率 < 10% or 削減量 < 1GB          → 圧縮しても効果小
アンチチート検出                      → アンチチートあり（自己責任で）
30日以内に更新                        → 更新が多い（圧縮が解けやすい）
上記以外                              → 圧縮推奨
```

これとは独立に、**長期未起動 × 大容量 × 圧縮が効かない** の組み合わせには
「削除すれば N GB 空きます（圧縮の約 M 倍）」という事実を添える。
ツールが削除を実行することはない。判断はユーザーがする。

### なぜ「削除したほうが得」を出すのか

ユーザーが欲しいのは空き容量であって、圧縮されたゲームではない。

60GB のゲームで実測圧縮率が 8% なら、圧縮しても 4.8GB しか空かない。
3 年起動していないなら、削除すれば 60GB 空く。12 倍の差がある。
ここで「圧縮しても 4.8GB です」とだけ言って終わるツールは、問題を解決していない。

「これは圧縮しても無駄です」と言えることが、見積もりの正直さの証明でもある。

`--no-uninstall-advice` で無効化できる。

## 圧縮率の見積もり方

コミュニティ製データベースは使わない。ネットワークにも接続しない。
**対象マシンの実データを読んで測る。**

```
1. フォルダ内のファイルを拡張子カテゴリ別に層化抽出
   （論理サイズの約 6%、64MB〜1GB。フォルダが大きいほどサンプルも増やす）
2. 大きいファイルは内部の 8 箇所から等間隔に読む（先頭だけだとヘッダに引きずられる）
3. 読んだデータを 32KiB チャンクに切って個別に圧縮し、比率を測る
4. カテゴリ別の実測比率をバイト数で重み付けして全体に外挿
   （サンプル対象の選択は決定論的。実行のたびに数字が変わることはない）
```

### 32KiB チャンクで測る理由

WOF の LZX は 32KiB のチャンク単位で独立に圧縮する。実効的な参照窓は 32KiB しかない。
ファイル全体を 1 ストリームとして圧縮した比率で見積もると、**実際より良い数字が出てユーザーを裏切る。**

この挙動は `ChunkedBrotliProbeTests.チャンク境界を跨ぐ繰り返しでは全体圧縮より控えめな値になる` で検証している。

### 一切書き込まない

見積もりのために試し圧縮するツールもあるが、本ツールは読むだけ。
`scan` は完全に無害。`LibraryScannerTests.走査は一切書き込みを行わない` で保証している。

### 校正結果（実機検証済み）

`ChunkedBrotliProbe` は Brotli(quality=9, window=15) を LZX の代理として使っている。
Windows 11 実機で `compact.exe /EXE:LZX` の実測値と突き合わせた結果:

| プロファイル | 実測 LZX | プローブ推定 | 誤差 |
|---|---|---|---|
| コード類 (.dll/.json/.xml) | 36.4 % | 38.2 % | +1.8 pt |
| Unity バンドル (.bundle) | 84.2 % | 86.0 % | +1.8 pt |
| 動画 (.webm) | 97.8 % | 96.3 % | −1.5 pt |
| 独自アーカイブ (.arc) | 29.4 % | 26.3 % | −3.1 pt |

最小二乗で求めた補正係数は **k = 1.0001**。系統誤差はほぼ無く、`calibration = 1.0` のままでよい。
残差は平均 2.1 pt / 最大 3.1 pt で、これは系統バイアスではなくコンテンツ種別ごとのばらつき。

### 実タイトルでの精度（正直な数字）

上の校正は等質なファイル群に対するもの。実際のゲームフォルダ（異種混合）では
ばらつきが大きくなる。実タイトル 5 本の層化複製を実際に LZX 圧縮して検証した結果、
**誤差は平均 2.7 pt / 最大 5.7 pt**（`docs/RESEARCH.md` §6）。

つまりこのツールの見積もりは **±6 pt 程度ぶれることがある推定値**であり、
外れた 2 本はいずれも「実際より縮まない」と控えめに言う方向だった。
「必ず N% 削減」という類の主張はしない。

### 32 KiB チャンクの妥当性も実測で確認した

同じデータを「全体を1ストリームとして圧縮」した場合と比べる:

| プロファイル | 実測 LZX | LZMA（全体） | 乖離 |
|---|---|---|---|
| コード類 | 36.4 % | 25.8 % | **−10.6 pt** |
| Unity バンドル | 84.2 % | 71.3 % | **−12.9 pt** |
| 独自アーカイブ | 29.4 % | 20.3 % | **−9.1 pt** |

全体圧縮で見積もると 1割前後 過大に良い数字が出る。
一方 zlib（参照窓が元々 32 KB）はチャンク有無でほぼ変わらず、
**この差が参照窓サイズに由来することの裏付けになっている。**

## 構成

```
src/
  SteamChecker.Core/       net10.0 / OS 非依存 / テスト対象の本体
    Steam/                          VDF パーサ、libraryfolders / appmanifest / localconfig
    Analysis/                       フォルダ走査、特徴検出、圧縮率推定、判定エンジン
    Compression/                    compact.exe 実行、操作ログ
    Presentation/                   日本語の文言（判定ロジックからは分離）
  SteamChecker.Cli/        net10.0 / コマンドライン版
  SteamChecker.App/        net10.0-windows / WPF 版（表示のみ。判定ロジックは持たない）
tests/
  SteamChecker.Tests/      テスト本体（xUnit）
  SteamChecker.TestRunner/ NuGet が使えない環境用の依存ゼロランナー
```

`Core` は Windows API に直接依存しない（`IFileSystem` 抽象と、アプリ層から注入する
レジストリ参照デリゲートで分離）。おかげで Linux 上でも判定ロジックを全てテストできる。

## ビルドと実行

```bash
# 通常（Windows / NuGet あり）
dotnet build
dotnet test

# NuGet に到達できない環境
dotnet run --project tests/SteamChecker.TestRunner

# 実行
dotnet run --project src/SteamChecker.Cli -- scan
```

### CLI

```
# Phase 0（読み取り専用・既定で使える）
steamchecker scan [--all] [--json] [--no-uninstall-advice]
steamchecker history

# Phase 1（実験段階・--experimental が必要）
steamchecker compress <appid> --experimental [--algorithm LZX|XPRESS16K|XPRESS8K|XPRESS4K] [--yes]
steamchecker restore  <appid> --experimental
steamchecker restore  --all   --experimental

共通オプション:
  --steam <パス>     Steam のインストール先を明示する
  --journal <パス>   操作ログの保存先を変える
  --dry-run          実際には書き込まない
  --assume-ntfs      ファイルシステム判定を飛ばす（Windows 以外での動作確認用）

scan の閾値調整:
  --min-saved-mb <数>       この量未満しか空かないなら「効果小」（既定 1024）
  --min-saved-percent <数>  この割合未満しか縮まないなら「効果小」（既定 10）
  --unplayed-days <数>      長期未起動とみなす日数（既定 180）
  --uninstall-min-mb <数>   削除候補として扱う最小サイズ（既定 20480）
  --large-saving-mb <数>    「大きく空く」と表示する閾値（既定 5120）
```

### 出力例

```

   Retro Strategy
     25日前にプレイ / 42.0 GB / 圧縮見込み 24.3 GB
     · 24.3 GB 空きます
     · 最終更新から 400 日。圧縮した状態が保たれやすい構成です

■ 圧縮可（要 確認）  (1 件)

     1日前にプレイ / 48.0 GB / 圧縮見込み 26.1 GB

       実績が少ないため既定では対象外にしています

■ 圧縮しても効果小  (1 件)
   Cinematic RPG
     3年1ヶ月未起動 / 61.0 GB / 圧縮見込み 1.2 GB
     · 3年1ヶ月 未起動
     · 削除すれば 61.0 GB 空きます（圧縮の約 50 倍）

   Fast Loader FPS

       読み込みが遅くなる可能性があります
```

## 配布の透明性

- **無署名である。** コード署名証明書を持っていないため、実行時に SmartScreen の警告が出る。
  これをごまかす手段は取らない（取れない）。ソースからのビルドを推奨する

### SmartScreen で実際に出る画面（2026-07-30 実機確認）

Release からダウンロードした exe を初回実行すると、次の警告が出る:

> **Windows によって PC が保護されました**
> Microsoft Defender SmartScreen は認識されないアプリの起動を停止しました。
> このアプリを実行すると、PC が危険にさらされる可能性があります。
> アプリ: SteamChecker.App.exe / 発行元: 不明な発行元

これは無署名 exe に対する Windows の標準動作。実行するには
**「詳細情報」をクリック → 「実行」ボタン**。実行前に `SHA256SUMS.txt` と
ダウンロードした exe のハッシュ（`Get-FileHash <exe>`）の一致を確認することを推奨する。
この警告に不安がある場合は、ソースからビルドすれば警告は出ない。

### どちらをダウンロードすればいいか

| | 軽量版 `SteamChecker.App.exe`（0.3 MB） | 完全版 `SteamChecker.App-selfcontained.exe`（133 MB） |
|---|---|---|
| 初回起動 | **約 2 秒** | 約 11 秒 |
| 2回目以降 | 約 0.9 秒 | 約 1 秒 |
| 必要なもの | [.NET 10 デスクトップランタイム](https://dotnet.microsoft.com/download/dotnet/10.0)（未導入なら Windows が案内を出す） | なし |

**迷ったら軽量版**。ランタイムが入っていなければ Windows がダウンロード先を教えてくれる。
一度入れれば他の .NET アプリでも使い回される。

### 初回起動が遅い理由（実測済み）

初回起動を支配しているのは、**新しい実行ファイルに対する Windows Defender のスキャン**で、
ほぼファイルサイズに比例する（`docs/RESEARCH.md` §7）。
JIT や .NET ランタイムの展開ではない。実際、同じ 133MB の exe でも
一度実行した後なら約 1 秒で起動する。

そのため「起動を速くする定番手法」である ReadyToRun は、
ファイルを 149MB に太らせるので**採用していない**（測ったら逆効果だった）。

### 起動したらすぐ一覧が出る

起動直後にインストール済みタイトルの一覧（名前・サイズ・最終プレイ）が表示される。
圧縮率の実測はライブラリの規模により数分かかるため、
**「圧縮見込みを解析」ボタンを押したときだけ**実行する。
起動しただけで CPU とディスクを使い続けることはない。

### 進捗ゲージはバイト数で進む

解析中・圧縮中は進捗ゲージと残り時間の目安が出る。いつでも中止できる。

このゲージは**件数ではなくバイト数**で進む。所要時間は容量にほぼ比例するため、
「44 件中 40 件終わったのにゲージは 40%」という表示になることがある。
これは正しい表示で、残りに 100GB 級のタイトルが控えていることを意味する。
件数で測ったゲージのほうが気持ちよく進むが、残り時間について嘘をつく。
- **通信ゼロ。** ソースコード（`src/`）にネットワーク API（`System.Net` / `HttpClient` /
  `Socket` 等）の使用は一切ない。`grep -r "System.Net\|HttpClient" src --include="*.cs"` で確認できる。
  Steam の情報はすべてローカルファイル（`libraryfolders.vdf` / `appmanifest_*.acf` /
  `localconfig.vdf`）から読む
- **依存ゼロ。** 製品コード（Core / Cli / App）の NuGet 依存は無い。テストのみ xUnit を使う
- **再現ビルド:** `dotnet publish src/SteamChecker.Cli -c Release -r win-x64 --self-contained -p:PublishSingleFile=true`
- リリース成果物を配布する場合は SHA-256 を添付する

## 免責

本ツールはゲームファイルに対して Windows 標準の透過圧縮を適用する。
可逆であり、`restore` でいつでも元に戻せるが、**動作を保証するものではない。**

- 圧縮はファイルへの書き込みで自動的に解除される。ゲームを更新するとその分は元のサイズに戻るので、
  また縮めたいときはツールをもう一度実行する（常駐して自動でやる機能は作らない方針。D-018）
- NTFS 以外（ReFS / Dev Drive / exFAT）では動作しない
- HDD では断片化により逆効果になる場合がある
- 全ての操作は `%LOCALAPPDATA%\SteamChecker\operations.jsonl` に記録される
